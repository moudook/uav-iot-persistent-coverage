ISSUE 5: opp_env run -c only passes first word as command (CRITICAL)
--------------------------------------------------------------------------
SYMPTOM: `opp_env run -c "mkdir -p /path && cp file1 file2"` → "mkdir: missing operand"
ROOT CAUSE: opp_env internally uses `nix develop --command` which calls execvp().
  Only the FIRST whitespace-delimited token is treated as the executable.
  Shell operators (&&, ;, |) and environment variable assignments (VAR=val cmd)
  are NOT processed because there's no shell wrapper.
AFFECTED COMMANDS THAT WORK:
  - `opp_env run -c "opp_run -v"` ✓
  - `opp_env run -c "opp_run -u Qtenv -c Config -f file"` ✓
  - `opp_env run -c "ls /path/"` ✓
AFFECTED COMMANDS THAT FAIL:
  - `opp_env run -c "mkdir /path && cp file /path/"` ✗
  - `opp_env run -c "NEDPATH=/x opp_run ..."` ✗ (env var assignment needs shell)
  - `opp_env run -c "bash script.sh"` ✗ (output swallowed, script may not execute)
SEVERITY: CRITICAL — made scripting impossible. Forced all work to be single-command.
WORKAROUND: Run one command at a time. Chain from the OUTER bash, not inside -c.

ISSUE 7: OMNeT++ NED loader scans CWD recursively (CRITICAL)
--------------------------------------------------------------------------
SYMPTOM: When running `opp_run` from workspace root, OMNeT++ scans ALL subdirectories
  for NED files. It finds files in `inet-4.6.0/examples/`, `inet-4.6.0/showcases/`,
  etc. and reports:
  "Declared package 'inet.examples.adhoc.hostautoconf' does not match expected
  package 'inet-4.6.0.examples.adhoc.hostautoconf'"
ROOT CAUSE: OMNeT++ treats CWD as a NED source folder and recursively scans it.
  Directory names like `inet-4.6.0` don't match declared package prefixes like `inet`.
  The path-derived expected package `inet-4.6.0.examples.*` conflicts with declared
  `inet.examples.*`.
FIX APPLIED:
  1. Moved examples/showcases/tutorials/templates OUTSIDE workspace entirely
  2. Added `ned-package-exclusions = inet-4.6.0;simu5g-1.4.3;omnetpp-6.4.0` to ini
  3. Created `sim/package.ned` with `package sim;` for our NED files
  4. Added `ned-path = sim;inet-4.6.0/src;simu5g-1.4.3/src` to specify correct paths
SEVERITY: CRITICAL — prevented simulation from loading entirely.


ISSUE 8: NED package name mismatch due to versioned directory names
--------------------------------------------------------------------------
SYMPTOM: Even after excluding top-level directories, files under `inet-4.6.0/src/`
  still get wrong expected packages: `inet-4.6.0.src.inet.applications.clock`
  instead of `inet.applications.clock`.

FIX: `ned-package-exclusions = inet-4.6.0;simu5g-1.4.3;omnetpp-6.4.0` excludes

  source directories where path-derived packages match declarations.
SEVERITY: CRITICAL — without exclusions, hundreds of NED loading errors.


ISSUE 9: NED files load but C++ classes not found (simu5g::LteChannelControl)
--------------------------------------------------------------------------
SYMPTOM: NED loader finds and resolves all types correctly, but at runtime:
  Class "simu5g::LteChannelControl" not found — perhaps its code was not linked in
ROOT CAUSE: The NED files define the module types, but the C++ implementations live
  in shared libraries (libsimu5g.so, libINET.so). In `opp_env run -c` isolated mode,
  these libraries are NOT automatically loaded. The opp_env shellHook only sources
  the OMNeT++ setenv, not INET or Simu5G setenv scripts.
FIX NEEDED: `load-libs` directive in omnetpp.ini. But see Issue 10.
SEVERITY: CRITICAL — simulation loads in Qtenv but crashes on network setup.


ISSUE 10: load-libs separator — comma vs semicolon vs space (RESOLVED)
--------------------------------------------------------------------------
SYMPTOM: `load-libs = inet-4.6.0/src/libINET.so,simu5g-1.4.3/src/libsimu5g.so`
  Error: Cannot load library '...libINET.so,simu5g-1.4.3/...'
  Same error with semicolon separator.
ROOT CAUSE: OMNeT++ load-libs uses SPACE as separator, not comma or semicolon.
  Web source: Google Groups omnetpp thread by Attila (OMNeT++ developer)
  and OMNeT++ 4.x manual: "a space-separated list of shared libraries"
FIX: `load-libs = inet-4.6.0/src/libINET.so simu5g-1.4.3/src/libsimu5g.so`
SEVERITY: RESOLVED — simulation now loads all C++ libraries correctly.

## Verified REAL - fix these

1. Mixed sd conventions. The learned rows in `results_main.csv` use sample SD (`ddof=1`), while `results_ablation*.csv` and several `ab_*.py` JSON outputs stored population SD (`ddof=0`). `fill_tokens.py` also used population SD for its ablation yardstick while using sample SD for paired `pstd`; `summary.py` reported stored `CK_std` instead of recomputing it from the per-seed values. `make_tables.py` already recomputes sample SD when per-seed values are present, so its fallback is only an issue for rows without those values.

   **What is wrong in the original suggestion:** `ab_observation.json` does contain `per_seed_CK` for its learned arms, and `make_tables.py` reads those arrays and prints sample SD for them; that table does not currently fall back to population SD. The observation and credit tables render learned arms, not rule baselines, so saying that those captions fail to disclose the rules' scene-axis spread is inapplicable. Also, current rule rows in `results_main.csv` have no `CK_std`, so the main table does not print a rule-baseline $\pm$ or disclose such an axis; the earlier assertion that it does is wrong for this artifact generation. The runner's diagnostic rule spread is across evaluation scenes, unlike the learned controller's training-seed spread.

   **Fix applied:** all relevant ablation/observation/credit spread producers now use sample SD (with zero for fewer than two observations); rule-baseline scene spreads use sample SD as well. The ablation resume path recalculates `CK_std` from its saved per-seed vector, so old run-log entries are normalized without retraining. `fill_tokens.py` now uses sample SD for both yardsticks and recomputes observation-arm spreads from their seed vectors; `summary.py` does the same for stored JSON and ablation rows. Existing measurement means and per-seed values are unchanged.
2. CI critical-value fallbacks in `fill_tokens.py`. Without SciPy, paired and gap intervals substituted `z=1.96` for Student-t; at eight seeds that is about 17% narrower. **What is wrong in the suggestion:** it understates the failure modes and calls this an SD fallback (the SD is still sample SD). A separate ablation-summary path used a critical value of zero, producing zero-width intervals; the Bonferroni path silently omitted its adjusted bound; paired p-values became NaN. So simply replacing the three noted z fallbacks would not fully fix the behavior. **Fix applied:** inference now goes through a shared SciPy requirement helper; if SciPy is missing, t-based intervals/adjustments fail explicitly with an install instruction. The normal-approximation, zero-width, and swallowed-error paths are removed. A regression test simulates missing SciPy. No experiments are rerun and no measured values are changed; report-token generation now stops instead of emitting degraded inference.
3. Dead ablation arms. Denied == 0.0 in all 60 ablation rows, nominal and stress. no-arbitration removed nothing (+0.013 is noise, not evidence). no-reserve is bit-identical to Full in the nominal config (failures disabled; reserve never deploys; stress correctly diverges). no-degraded is bit-identical to Full on seeds 2 and 4 (and seed 2 in stress): no disconnection happened there, so D_t == 0 and the arm is information-free on those seeds.
4. Duplicate generations + last-wins merge. The live artifacts are one consistent generation (results_main MAPPO == results_ablation.csv Full == ab_credit arm A == ab_energy arm A; identical per-seed vectors, CK 0.6740706). `results_ablation_parta/partb.csv` are orphan pre-charger-fix artifacts (all-zero MinBattery signature) referenced by NO script - delete them or archive them, not merge them. `make_tables.py:376` (`by = {r["model"]: r ...}`) silently keeps the last row; add an explicit dedup rule or refuse on config-hash mismatch.
5. Table XIV `single_pad: NA`. The policy can be evaluated zero-shot: `obs_dim` is unchanged by pad count (pad bearing is always three features for the nearest pad), while centralized `state_dim` changes by one per pad. `MAPPO.load()` loads both actor and critic, so constructing MAPPO with the single-pad `state_dim` then loading the full checkpoint would mismatch the critic's input layer. **What is wrong in the original suggestion:** the current evaluator excludes `single_pad` in `SAME_DIM_REGIMES`, so it never actually attempts that failing load; the `NA` is an intentional skip, not a recorded load exception. Also, only the training-time critic dimension differs; saying no nominal policy can be loaded is too broad. Actor-only loading is valid for frozen execution because `eval_agent()` calls `agent.act()` and does not use the critic. Finally, “a real number is free” assumes the trained `.pt` files are available; none are currently present in this repo, so the reported score cannot be remeasured from these files alone. **Fix applied:** `MAPPO.load_actor()` restores only the policy weights; `eval_stress.py` now includes `single_pad` among actor-compatible regimes and uses this loader. It also stops explicitly if the requested run has no trained checkpoints, rather than writing empty/NaN learner results. A regression test checks unchanged actor input size, the one-feature critic shift, actor-only checkpoint loading, and a one-step evaluation. No retraining is required, but the actual frozen-policy score still requires the original checkpoints.
6. Action-repeat conclusion overstated. Trained hold=4 (`old/launch_ar_fixed.ps1`: --n-steps 500 --action-repeat 4) but evaluated hold=1 (`eval_ckpt.py` has no --action-repeat). 0.9086 vs 0.9512 measures cross-MDP transfer, not "repetition hurts the deployed policy". Also: the exp_ar_eval seed metas never log action_repeat. Reword Section VIII-F, and run the hold=4 eval (add the flag) or retrain with gamma^4.
7. Shaping sign inverted - the big one. Report Section III-O and `env.py:1333` (and `:1342`, energy potential) compute kappa*(prev_phi - gamma*phi_after), which is exactly -F for Ng's reward-max form F = gamma*Phi' - Phi. With Phi = -dist <= 0 this rewards RETREATING from sensors and penalizes approach, and the sum does not exactly telescope. The headline (exp_ego_eval, 0.9512) was trained with shape=0.5. Two acceptable resolutions: (a) fix the sign in both terms + III-O and rerun ego+shape (2-3 days wall-clock); (b) keep the number, reword: "dense reward shaping", drop "potential-based / policy-invariant". The frozen-policy measurements remain valid as artifacts; the mechanistic claim does not.

Also, small but fix in the same pass: MaxRefresh == 2000 in every stress row (right-censored, discriminates nothing) - drop or recompute it in the stress table.
